.NET 9/10 & Entity Framework Core

Toàn Diện Về Entity Framework Core

Hướng dẫn chuyên sâu từ kiến trúc ORM, so sánh các phương pháp tiếp cận đến Cấu Hình Code-First Chi Tiết và Toàn Tập Quy Trình Build & Chạy Migration trong thực tế.

Chủ đề:

1 Entity Framework (EF) Là Gì?

Entity Framework (EF Core) là bộ công cụ ORM (Object-Relational Mapper) hàng đầu của Microsoft dành cho nền tảng .NET. Nó đóng vai trò là "cầu nối" giúp lập trình viên thao tác với cơ sở dữ liệu quan hệ (SQL Server, PostgreSQL, MySQL...) hoàn toàn bằng các đối tượng C# (Object) và câu lệnh LINQ mà không cần viết các câu lệnh SQL thô phức tạp.

Mô Hình Hoạt Động Của Entity Framework

Ứng Dụng .NET / C#

Class Entity: Room, User

Truy vấn: _context.Rooms.Where(...)

Entity Framework Core

  • ✔ DbContext: Quản lý kết nối & phiên làm việc
  • ✔ LINQ Provider: Biên dịch C# thành SQL
  • ✔ Change Tracker: Theo dõi thêm/sửa/xóa

Cơ Sở Dữ Liệu Quan Hệ

SQL Server, PostgreSQL, MySQL, SQLite

Bảng: [Rooms], [Users]

Tăng Tốc Độ Phát Triển

Không cần viết boilerplate code đọc `SqlDataReader`, tự động map dữ liệu vào object C#.

An Toàn Kiểu (Type-Safe)

Mọi thuộc tính đều được IDE kiểm tra cú pháp ngay lúc gõ code thay vì runtime lỗi.

Chống SQL Injection

EF tự động tham số hóa (parameterize) mọi biến trong LINQ, bảo vệ an toàn tối đa cho DB.

2A Hướng Dẫn Cấu Hình Code-First Chi Tiết (Từng Bước)

Cốt Lõi Hệ Thống Booking-App

Để cấu hình một dự án .NET theo chuẩn Code-First, hệ thống trải qua 4 bước thiết lập cấu hình cốt lõi dưới đây:

1

Cài Đặt Các Gói NuGet & Công Cụ EF Core CLI

Mở Terminal tại thư mục project API (src/BookingApi) và cài đặt 3 gói bắt buộc:

# 1. Driver kết nối SQL Server
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
# 2. Bộ công cụ tạo Migration và Scaffold
dotnet add package Microsoft.EntityFrameworkCore.Tools
# 3. Cài đặt công cụ dòng lệnh dotnet-ef toàn cục trên máy tính
dotnet tool install --global dotnet-ef
2

Cấu Hình Chuỗi Kết Nối (Connection String) Trong appsettings.json

Khai báo kết nối đến máy chủ SQL Server của bạn. Cấu hình thực tế trong file src/BookingApi/appsettings.json: 

{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=BookingSystemDb;Trusted_Connection=True;TrustServerCertificate=True;"
  }
}
💡 Gợi ý: TrustServerCertificate=True giúp tránh lỗi từ chối chứng chỉ SSL khi kết nối trên môi trường local.
3

Đăng Ký DbContext Vào Dependency Injection Trong Program.cs

Thông báo cho ứng dụng biết sử dụng AppDbContext và kết nối với nhà cung cấp SQL Server: 

var builder = WebApplication.CreateBuilder(args);

// Đăng ký AppDbContext với vòng đời Scoped tự động
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));
4

Xây Dựng Entity & Cấu Hình Fluent API Trong AppDbContext.cs

Có 2 cách để cấu hình bảng: Data Annotations (đặt attribute trực tiếp trên property) và Fluent API (khuyên dùng trong OnModelCreating vì không làm bẩn class Entity và hỗ trợ cấu hình nâng cao):

// 1. Entity C# thuần (POCO) 
public class Room
{
    public Guid Id { get; set; }
    public string Name { get; set; }
    public decimal HourlyRate { get; set; }
    
    // Token chống xung đột đặt phòng đồng thời
    public byte[] RowVersion { get; set; }
    
    public ICollection<Booking> Bookings { get; set; }
}
// 2. Fluent API trong AppDbContext.cs 
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Room>(entity =>
    {
        entity.HasKey(e => e.Id);
        entity.Property(e => e.Name).IsRequired().HasMaxLength(100);
        entity.Property(e => e.HourlyRate).HasPrecision(18, 2);
        
        // Cấu hình Optimistic Concurrency
        entity.Property(e => e.RowVersion).IsRowVersion();
    });
}

2B Quy Trình Run & Build Migration Toàn Tập (Từ A Đến Z)

Quản Lý Lịch Sử Database

Migration là cơ chế ghi lại từng "bước tiến hóa" của cơ sở dữ liệu giống như các commit trong Git. Khi bạn thêm/sửa thuộc tính trong C#, bạn cần chạy quy trình build và update migration theo các bước sau:

Cơ Chế EF So Sánh & Thực Thi Migration
1. ModelSnapshot.cs

Bản chụp trạng thái hiện tại của toàn bộ model C#.

So sánh với code mới
2. File Migration (.cs)

Sinh ra hàm Up() (khi nâng cấp) và Down() (khi rollback).

dotnet ef migrations add
3. [__EFMigrationsHistory]

Bảng ngầm trong SQL Server lưu danh sách các migration đã chạy.

dotnet ef database update

Bảng Tra Cứu Toàn Bộ Lệnh Migration Thường Dùng:

Bước 1: Build & Tạo Migration Mới Terminal: src/BookingApi

Trước khi tạo migration, EF sẽ tự động biên dịch (build) dự án. Nếu code có lỗi cú pháp, lệnh sẽ dừng lại.

dotnet ef migrations add TenMigrationMoi

Ví dụ trong dự án của bạn: dotnet ef migrations add MeetingRoomPivot

Bước 2: Đẩy Thay Đổi Xuống SQL Server Áp dụng schema

EF đọc bảng __EFMigrationsHistory trên SQL Server và chỉ chạy các lệnh SQL của những migration chưa có.

dotnet ef database update
Bước 3: Kiểm Tra Tình Trạng Các Migration Xem trạng thái

Hiển thị danh sách các migration đã được apply vào database và migration nào còn đang chờ (Pending):

dotnet ef migrations list
Xử Lý Sự Cố: Rollback / Hủy Bỏ Migration Sai Cực kỳ quan trọng
Trường hợp 1: Bạn vừa chạy add nhưng chưa chạy update:
dotnet ef migrations remove
Lệnh này sẽ xóa file migration vừa tạo ra một cách an toàn.
Trường hợp 2: Bạn đã lỡ chạy database update rồi nhưng muốn rút lại:
# B1: Quay lui database về migration trước đó
dotnet ef database update TenMigrationPhiaTruoc
# B2: Bây giờ mới xóa file migration
dotnet ef migrations remove
Nâng Cao: Xuất File SQL Để Đưa Lên Server Thật (CI/CD) Production Ready

Khi deploy lên server thật, DBA thường không cho chạy lệnh CLI. Bạn có thể xuất ra file script SQL tự động kiểm tra bảng:

dotnet ef migrations script -i -o deploy_script.sql

Cờ -i (Idempotent) đảm bảo script có lệnh kiểm tra IF NOT EXISTS an toàn khi chạy nhiều lần.

3 Phương Pháp Database-First (Reverse Engineering)

Dành Cho Dự Án Đã Có Sẵn Cơ Sở Dữ Liệu

Với Database-First, quy trình đi ngược lại hoàn toàn: Cơ sở dữ liệu đã tồn tại từ trước (được thiết kế bằng SSMS, Oracle, MySQL...). Bạn sử dụng công cụ dòng lệnh của EF Core để quét schema database và tự động sinh ngược ra (scaffold) các file C# Entity và DbContext.

Sơ Đồ Quy Trình Database-First (Reverse Engineering)
01
Cơ Sở Dữ Liệu Đã Có Sẵn

Các bảng, Views, Stored Procedures, Khóa ngoại đã được tạo bởi DBA trong SQL Server.

02
Chạy Lệnh Scaffolding

EF Core CLI đọc metadata từ DB engine và dịch các bảng thành class C#.

dotnet ef dbcontext scaffold
03
Tự Động Sinh Code C#

Sinh ra các file `Room.cs`, `Booking.cs` và `MyDbContext.cs` sẵn sàng để truy vấn bằng LINQ.

Lệnh Scaffold trong EF Core:
dotnet ef dbcontext scaffold "Server=localhost;Database=BookingSystemDb;Trusted_Connection=True;TrustServerCertificate=True;" Microsoft.EntityFrameworkCore.SqlServer -o Models --context-dir Data --context AppDbContext
Ưu điểm của Database-First
  • Hoàn hảo khi làm việc với hệ thống cũ (Legacy database) đã có sẵn hàng trăm bảng.
  • DBA có thể tận dụng toàn bộ sức mạnh của SQL Server (Triggers, Stored Procedures, Partitioning) mà không bị giới hạn bởi ORM.
  • Không tốn thời gian ngồi gõ lại các class C# thủ công.
Nhược điểm
  • Mỗi khi sửa schema trên DB, bạn phải chạy lại lệnh scaffold (có nguy cơ ghi đè mất code tùy biến thêm nếu không dùng `partial class`).
  • Không có file Migration tự động theo dõi trong Git.

4 Phương Pháp Model-First (Kéo Thả EDMX)

Lịch Sử (Chủ Yếu Trong EF6 Cũ)

Model-First là cách tiếp cận phổ biến trong thời kỳ Entity Framework 4, 5, 6 (.NET Framework). Lập trình viên không bắt đầu bằng Code hay Database, mà mở giao diện trực quan trong Visual Studio (EDMX Designer) để vẽ các hình chữ nhật (Entity) và kéo các đường nối mũi tên (Quan hệ). Sau đó, Visual Studio sẽ sinh ra cả file script SQL để tạo DB lẫn mã C#.

Sơ Đồ Quy Trình Model-First (Visual Designer)
Vẽ Sơ Đồ Trực Quan

Dùng Visual Studio kéo thả các hộp Entity và quan hệ trong file .edmx

➔ Sinh ra 2 nhánh ➔
Nhánh 1: Cơ sở dữ liệu
Sinh Script DDL (.sql)

Chạy script SQL để tạo các bảng trong Database.

Nhánh 2: Mã nguồn
Sinh C# POCO Classes

Tự động sinh ra các file `.cs` cho ứng dụng.

Lưu Ý Quan Trọng Với EF Core

Microsoft đã loại bỏ hoàn toàn Model-First (file .edmx) kể từ khi ra mắt Entity Framework Core. Lý do là file XML `.edmx` rất cồng kềnh, thường xuyên xảy ra xung đột không thể tự giải quyết khi nhiều lập trình viên cùng merge Git (Merge Conflict), và làm chậm Visual Studio. Thay vào đó, EF Core chuyển sang tập trung hoàn toàn vào Code-First và Scaffolding.
